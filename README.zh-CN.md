# Rich Mindmap

[English](README.md) · **简体中文**

把 Markdown 的缩进列表渲染成可编辑的思维导图，支持优先级、进度、旗帜标记与节点备注。
原始数据始终是普通 `.md` 文件 —— 你和 AI 读写的是同一份、结构清晰的 Markdown。

![示例文件在导图视图中打开：五条按分支着色的主干、优先级圆标、进度饼图、旗帜标记、一个显示子节点数的折叠分支，以及贴着选中节点的悬浮工具栏。](docs/images/screenshot.png)

*上图是[示例文件](examples/conference-talk.md)在导图视图中的样子。*

## 与其他思维导图插件的区别

Obsidian 社区里的思维导图插件大致分两类：一类是基于 [markmap](https://markmap.js.org/) 的**只读预览**（把笔记渲染成导图但不能在导图上编辑），另一类建在 Obsidian Canvas 上、数据是 `.canvas` JSON。

本插件采用与 markmap 相同的*层级模型* —— 标题加嵌套列表 —— 所以你一直用那类插件预览的笔记可以直接在这里打开、在图上编辑。但它刻意**不**实现 markmap 自己的方言：`markmap:` frontmatter 选项与 `<!-- markmap: fold -->` 魔法注释。折叠状态在这里存于 frontmatter 的 `mindmap-collapsed` 键，若同时有两个来源，写回时就必须裁决谁赢 —— 这与下面「写回只做五条归一化」的承诺冲突。

这个插件的取向是：

- **可以直接在导图上编辑**，而数据仍然是普通 Markdown 缩进列表 —— 没有自有格式、没有坐标、没有 JSON
- **支持优先级 / 进度 / 旗帜标记**，写在节点文字里，人和 AI 都能直接读写
- **节点可以带备注**，悬浮角标即可查看；备注存成节点下方的 Markdown 引用块，不装插件也读得到
- **有明确的文件安全边界**：只允许五条字节级归一化（见下），由往返属性测试锁定

可编辑这一点并非独有（社区里另有几个插件也做到了）；标记系统目前是这一类插件里少见的。

## 示例

把 [`examples/conference-talk.md`](examples/conference-talk.md) 拷进你的 vault 用导图视图打开即可。那份文件覆盖了：`##` / `###` 分节构成外层层级、7 档优先级、7 种旗帜颜色、覆盖每一档的进度值、嵌套列表、双链、行内格式，一个**不是**标记的括号组，一个记在 `mindmap-collapsed` 里的折叠标题，以及被插件隐形携带、不显示的 frontmatter 其他键与散文段落。（节点备注是后加的特性，示例文件与上面的截图还没用到它。）

下面是同一主题的中文版：

```markdown
---
mindmap: true
tags:
  - 演讲
  - 2026
讲者: 我
mindmap-collapsed:
  - 行程
---

# 技术演讲：驯服遗留代码

## 大纲

- (p1 100%) 开场故事 —— 凌晨三点那次告警
- (p1 67%) 核心论点
  - (p2) 遗留代码就是没有测试的代码
  - (p2 50%) 重构之前先要有安全网
    - 接缝与萌芽方法
    - 表征测试
  - (p3 33%) 少数情况下重写确实更划算
- (p2 17%) 现场演示
  - (flag:red) 必须全程离线预演 —— 会场网络从不可靠
  - (flag:orange) 录一段兜底视频
- (p4 0%) 收尾与行动号召

## 幻灯片

### 成稿

- (p2 60%) 在 [[演讲幻灯片]] 里起草
- (p5) 改造前后的调用图 —— 听众唯一会记住的**那张图**

### 打磨

- (p6) 无障碍检查：对比度、替代文本、`字号 >= 24pt`
- (p7 0%) 讲者备注

## 预演

走三遍，真正管用的是第三遍。

- (p1 83%) 控时 —— 正文 25 分钟，问答 5 分钟
- (p3 50%) 找同事走一遍
- (flag:yellow) 录下来回看 —— *难受但有效*
- (flag:green) 砍掉~~那段关于单体仓库的跑题~~

- (flag:blue) 机票已定
- (flag:purple) 酒店确认单归档在 [[出行 2026]]
- (flag:gray) 报销 —— 回来再说
- (备注) 这一行以括号开头，但不是标记

## 后续

1. 有序列表同样是节点，序号原样保留
2. 嵌套的也一样
  1. 连它们自己的序号一起

- (p4 0%) 发布文字版
- (p5 0%) 分享幻灯片与演示仓库

## 备注

标题与嵌套列表共同构成层级，所以上面每个 `##` 都是导图上的一个节点。**不在**
导图上的是：这段文字、frontmatter 里的 `tags` 与 `讲者` 键 —— 它们都被隐形携带。
用导图视图打开再切回源码模式，应当逐字节不变。
```

## 安装

**方式一：社区插件市场（推荐）**

设置 → 第三方插件 → 浏览，搜索 **Rich Mindmap**，安装并启用。市场页在 [community.obsidian.md/plugins/rich-mindmap](https://community.obsidian.md/plugins/rich-mindmap)。

需要 Obsidian **1.8.7** 或更高版本（界面语言设置要读 Obsidian 自身的语言，用的是那个版本才有的 API）。

**方式二：从 Releases 下载**

到 [最新 release](https://github.com/YounianC/obsidian-rich-mindmap/releases/latest) 下载 `main.js`、`manifest.json`、`styles.css` 三个文件，放进 vault 的 `.obsidian/plugins/rich-mindmap/` 目录，然后在 设置 → 社区插件 里启用「Rich Mindmap」。

**方式三：从源码构建**

```bash
git clone https://github.com/YounianC/obsidian-rich-mindmap.git
cd obsidian-rich-mindmap
npm install
npm run build          # 生成 main.js
```

然后把 `main.js`、`manifest.json`、`styles.css` 拷贝（或软链）到 `<你的 vault>/.obsidian/plugins/rich-mindmap/`。

> `main.js` 是构建产物，不在版本库里 —— 需要自己 `npm run build` 或从 release 获取。

## 数据格式

顶格的 ATX 标题（`#` 到 `######`）与嵌套列表（无序 `-`/`*`/`+` 与有序 `1.`/`1)`）**共同**构成层级 —— 这与 [markmap](https://markmap.js.org/) 的层级模型一致，所以为 markmap 系预览插件写的笔记可以直接在这里打开编辑。完整例子见上面的[示例](#示例)一节。

- 文件的第一个节点行是一级标题时，它就是根节点；否则根节点的文字取自文件名，文件里的第一个标题成为它的子节点。
- level 为 L 的标题挂到最近的 level < L 的标题下，找不到就挂到根下。所以 `# T` 后面直接跟 `### C` 时 C 挂在 T 下（允许跳级），同一份文件里的第二个 `# X` 挂在根下而不是嵌套进去。
- 标题名下的嵌套列表照旧：缩进深度决定层级，且缩进单位按标题各自记住。

在标题节点上，`Tab` 添加一个**列表项**子节点，`Enter` 添加一个复用同一 `#` 前缀的**同级标题**。标题节点做不到的事：

- **不能拖拽。** 把 `## A` 拖到 `## B` 下面，写出来是 `## B` 后跟 `## A`，重新解析时 A 会变成 B 的*兄弟* —— 这次移动被静默撤销了。格式表达不出「H2 嵌在 H2 里」，除非改写 `#` 的个数，而那是不允许的。
- **携带图上不可见内容时不能删除**（见下一段）。删了会删掉你看不见的东西。如果它携带的只有一个空行，删除是允许的，会连带整个章节（含子树）一起删掉。
- **根节点不能带标记**，因为文件里没有 H1 时根本没有可写标记的那一行。

标题名下的散文段落、表格、代码块、图片不在导图上显示，它们被隐形携带、写回时逐字节原位重放 —— 这也正是「携带这些内容的标题不允许删除」的原因。

### 行内标记

节点文字最前面的一个括号组，当组内每个 token 都是已知标记时才生效：

| 写法 | 含义 |
|---|---|
| `p1` … `p7` | 优先级（p1 红、p2 橙、p3 黄、p4+ 灰） |
| `0%` … `100%` | 进度（映射到 7 档饼图，原值保留不被改写） |
| `flag:red` `flag:orange` `flag:yellow` `flag:green` `flag:blue` `flag:purple` `flag:gray` | 旗帜 |

组合写在一起：`- (p1 60% flag:blue) 节点文字`

括号里出现未知 token 时整组按普通文字处理，例如 `- (备注) 说明` 不会被当成标记。

标记在标题节点上同样有效，写在 `#` 之后：`## (p2) 幻灯片`。**但要知道这会漏到插件之外**，而写在列表项上的标记不会 —— 标题文字在 Obsidian 里是可寻址的，所以 `(p2)` 会出现在大纲面板、搜索结果和图谱里，而且给一个标题加标记会让已有的 `[[笔记#标题]]` 引用失效。根节点的 H1 是唯一例外：那里拒绝标记，因为文件没有 H1 时无处可写。

### 备注

紧跟节点行的连续引用行就是这个节点的备注：

```markdown
- 三季度目标
  > 等 A 确认口径。
  > 参考上季度的留存拆分。
  - 拉新
```

导图上显示成一个角标，鼠标悬浮弹出气泡。选中节点后从工具栏的「备注」按钮编辑，Cmd/Ctrl + Enter 保存。

它是普通的 Markdown 引用块 —— 阅读视图里正常渲染，能被搜索到，不装这个插件也读得写得。中间隔了其它内容之后的引用块不算备注。根节点不支持备注，理由与标记相同：文件没有 H1 时无处可写。

只要你不动它，备注行就逐字节原样保留 —— `>备注`（无空格）、`>  备注`（两个空格）、Tab 缩进都不会被改写。只有两种操作会重写这几行：在导图里编辑这条备注，或把带备注的节点拖到另一层深度（缩进要跟着新层级走）。带备注的节点仍然可以删除、可以拖拽 —— 备注在图上是看得见的，不算「隐形携带的正文」。

### 行内格式

去掉标记括号组之后，节点剩余的文字会在导图上按行内 Markdown 渲染：

| 写法 | 渲染效果 |
|---|---|
| `**加粗**` | 加粗 |
| `*斜体*` | 斜体（只认 `*`，不认 `_`——`font_size` 里的下划线原样保留，不会被当成斜体） |
| `~~删除线~~` | 删除线 |
| `` `代码` `` | 行内代码 |
| `[[页面]]` / `[[页面\|别名]]` | 可点击的内部链接 |
| `[文字](url)` | 可点击的外部链接，在新标签页打开 |

未闭合或写错的标记（比如落单的 `**`、`*`）会原样按文字显示，不会报错也不会丢字符。`#标签`和原始 HTML **不会**被渲染——节点文字原样保留（这样 `#标签` 在 vault 其他地方仍然有效）。不支持图片：`![alt](url)` 不会被识别成图片语法，会退化成一个字面的 `!` 加一个普通的可点击链接（和写一个 `[text](url)` 效果相同），不会变成嵌入的图片。工具栏的加粗/斜体/删除线/链接按钮写的就是这套语法。

### 与 AI 协同

插件不内置 AI 调用。让任意 AI 直接编辑这个 `.md` 文件即可 —— 新增节点只需写一行普通列表项，不涉及 id、坐标或 JSON。文件在磁盘上变化后画布会自动重新解析并刷新，视口与选中保持不动；如果此时画布上还有一次没来得及落盘的本地修改，会被外部内容覆盖，并弹出提示告知。

列表块之外的内容（frontmatter 其他键、前言、代码块、尾部段落）永不被插件改写。

### 写回归一化

只要用导图视图打开过一个文件，即使不做任何修改再切回源码模式，Obsidian 也可能把它重写一次。这次重写会带来以下五种、且仅有这五种字节级变化：

- 不以换行结尾的文件会被补上一个尾换行；
- 松散列表（列表项之间夹着空行）会被压缩成紧凑列表。无序与有序是两个不同的列表，有序之间换分隔符（`1.` → `1)`）同样开一个新列表，**只有空行两侧属于同一个列表时才压缩**；
- `CRLF`（`\r\n`）统一转换为 `LF`（`\n`）；
- 列表缩进单位遵循文件原有的选择（2 空格、4 空格、Tab 等均原样保留），**且按标题各自推断**，所以不同章节用不同单位不会被改写。只有两种情形会被改写为每层 2 空格：某个列表块**内部**混用、无法归纳出单一一致单位；或**同一个标题名下**的多个列表块彼此单位不一致，此时统一到第一个能推断出的单位。`- ` 宽 2 而 `1. ` 宽 3，所以有序与无序混排时更容易撞上前一种情形；
- 行内标记统一按 优先级 → 进度 → 旗帜 的顺序写出（`(flag:blue 60% p3)` → `(p3 60% flag:blue)`）。

除此之外，任意合法 Markdown 逐字节不变 —— 包括 `*` / `+` 列表标记（不会被改成 `-`）、有序项的序号与分隔符（不会被重排，也不会被拉回从 1 开始）、每一个标题行的 `#` 个数与前后空白、frontmatter 结束围栏后的尾随空白，以及一切非节点行。

### 层级解析的已知局限

- 不带空格的 `##` 是合法的 CommonMark 空标题，但本插件不认。这条空格要求正是以 `#tag` 开头的行不被误判成标题的原因。
- 标题必须顶格。CommonMark 允许最多 3 个前导空格，本插件不认 —— 正是这一点让列表项续行里的 `  ## x` 不被误判成标题。
- Setext 标题（`A` 后跟 `===`）不认。
- ATX 闭合序列不剥离：`## A ##` 得到的节点文字是 `A ##`。字节能还原，但图上的文字带着尾部的 `##`。
- 列表块的边界是「连续的列表项」，两个条目之间的散文归入前一条目的续行且不切断块。所以 `- a` / 空行 / 散文 / `    - b` 里的 `- b` 被当成 `a` 的子节点，而 CommonMark 认为散文已经结束了列表、`    - b` 是代码块。与原有的 4 空格局限同源。

### 解析失败

如果文件内容无法被解析成思维导图（例如 frontmatter 或列表结构本身有问题），画布会显示一张错误提示卡片，并提供「切换到源码模式」按钮回到原始文本；这种情况下文件不会被插件写回或修改。

## 快捷键

| 按键 | 行为 |
|---|---|
| `Tab` | 添加子节点 |
| `Enter` | 添加兄弟节点 |
| `F2` / 双击 | 编辑文字 |
| `Delete` / `Backspace` | 删除节点及子树 |
| 方向键 | 在树中移动选中 |
| `Space` | 折叠 / 展开 |
| `Esc` | 取消编辑 / 取消选中 |
| `Cmd/Ctrl + 滚轮` | 缩放（另见下面「缩放」一节） |
| 空白处拖拽 | 平移 |

拖拽节点可改变父节点与同层顺序。

## 缩放

画布右上角是缩放控件：**适应窗口**、**缩小**、当前倍率、**放大**。中间那个百分比读数本身就是按钮，点它**恢复 100% 原始大小**——以视口中心为不动点，正在读的那块内容留在原地变大，不会被拉回根节点（想回根节点就先点「适应窗口」再点它）。倍率范围 20%–300%。

内容多的导图「适应窗口」会缩得很小（几百个节点常在 30% 上下，基本读不了）。如果你更希望一打开就是原始大小，设置 → Rich Mindmap → **打开导图时的缩放** 选 **100%（原始大小）**：视口会落在根节点所在的左中位置，从头开始按 100% 阅读。默认仍是**适应窗口**。这个设置只影响之后新打开的视图，已经开着的不受影响。

## 工具栏

选中一个节点后，画布上会出现一个贴着该节点的浮动工具栏，提供键盘之外的操作：加粗 / 斜体 / 删除线、标记面板（优先级、进度、旗帜，点选已生效项即取消）、插入 `[[链接]]`、编辑备注（多行输入框，`Cmd/Ctrl + Enter` 保存、`Esc` 取消），以及添加子/兄弟节点、删除、折叠/展开的按钮版本。备注按钮在选中根节点时禁用。

## 命令

- **新建思维导图**（文件夹右键菜单）—— 在该文件夹下创建 `未命名思维导图.md`（已存在则自动编号为 `未命名思维导图 1.md`、`2`……），内容为 `mindmap: true` frontmatter 加一个与文件名一致的一级标题，创建后立即在当前面板以导图视图打开。写入一级标题是为了让根节点可以直接在导图里改名；之后重命名文件不会同步改根节点文字。
- **切换思维导图 / 源码视图** —— 导图视图右上角标题栏还有一个「切换到源码模式」图标按钮，效果相同。手动切回源码后不会被自动打开逻辑再切回去，关掉标签页重新打开才会重新进入导图视图。
- **并排打开源码面板** —— 导图视图右上角标题栏也有对应的图标按钮。在左侧新开一个面板、以源码模式显示同一个文件，再点一次关闭；已经有面板在显示该文件时复用它，不新开第三个。两侧都可以编辑，内容的同步完全由 Obsidian 负责（两个视图读写同一个文件），插件不搬运任何文本。两点已知限制：**左侧打字后右侧导图约 2 秒才跟上**（那是 Obsidian 编辑器自己的保存节奏，导图侧写回则是 400ms）；**同一时刻只在一侧编辑** —— 两侧同时改会触发 Obsidian 自己的冲突合并，行为不由本插件控制。移动端不提供这个入口。
- **标记为思维导图（写入 frontmatter）** —— 写入 `mindmap: true`，之后打开该文件自动进入导图视图（可在设置中关闭）；对没有 frontmatter 的文件执行会新建一个 frontmatter 块。执行这条命令会把整个文件的换行符统一成 `LF`（即上面「写回归一化」里的 `CRLF` 那条），正文的可见内容不受影响。

开启「自动以思维导图打开」时，一个文件**已经**在某个面板上以导图视图显示后，其它显示同一文件的面板不会再被自动翻成导图 —— 源码分屏正是靠这条规则活下来的。代价是同一个文件想开两个导图面板时，第二个会停在源码模式，用上面的「切换思维导图 / 源码视图」手动切一次即可。

## 界面语言

界面支持英文与简体中文。设置 → Rich Mindmap → **界面语言** 三选：**跟随 Obsidian**（默认，括号里显示检测到的语言码）、**简体中文**、**English**。切换立即生效，命令面板里的命令名也会跟着变。

「新建思维导图」创建的文件默认名同样跟随语言（`未命名思维导图.md` / `Untitled Mindmap.md`）。已有文件永不被改名。

两条值得知道的局限：`zh-TW` / `zh-HK` 归到简体中文；`manifest.json` 里的插件描述只有英文——Obsidian 不支持本地化 manifest。

## 开发

```bash
npm install
npm run dev        # esbuild watch
npm test           # vitest
npm run typecheck
npm run check:purity
npm run check:i18n
```

`src/model/`（`collapse-state.ts`、`marks.ts`、`parser.ts`、`serializer.ts`、`tree-ops.ts`、`types.ts`）与 `src/view/layout.ts`、`src/view/camera.ts` 是纯函数层，不依赖 Obsidian API 与 DOM，由 `npm run check:purity` 强制校验，全部有单元测试覆盖。

## 发布

推一个版本号 tag 即自动构建并发布 release：

```bash
# 1. 改 manifest.json 的 version，并在 versions.json 加上对应项
# 2. 打 tag —— 名字必须与 manifest 的 version 一致，且不带 v 前缀
git tag -a 0.2.0 -m "..."
git push origin 0.2.0
```

GitHub Actions 会跑完类型检查、单元测试、纯函数层校验与构建，全部通过后才创建 release 并附上 `main.js`、`manifest.json`、`styles.css`。

## 项目状态

社区插件市场上的版本是 `0.1.1`。`0.2.0`（界面语言设置，同时把 Obsidian 的最低要求抬到 1.8.7）已在仓库里准备好，尚未发布；节点备注也已合入仓库，同样未发布。

- 纯函数层（解析、序列化、标记、备注、折叠状态、树操作、布局、相机、i18n）有 376 个自动化测试，含 Markdown 往返属性测试与对抗性输入测试。
- 视图层（渲染、缩放平移、键盘、拖拽、工具栏、备注角标与浮层）按设计是**人工验证**的，上架并不改变这一点。清单在 [docs/MANUAL-VERIFICATION.md](docs/MANUAL-VERIFICATION.md)：「能打开、能渲染、不损坏文件」那一节与全部 16 项 🔴 高危项已通过，**其余各节尚未走完**。其附录列出了开发过程中真实出现并修复的缺陷 —— 如果你要改动相关代码，那里是回归的高发区。

因为插件会重写你的笔记文件，**首次使用建议先在一个测试 vault、或已被 git 跟踪的目录里验证写回行为**，确认无误再指向重要笔记。
