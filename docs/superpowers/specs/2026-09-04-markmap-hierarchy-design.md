# 采纳 markmap 的层级语义（标题参与层级）— 设计文档

日期：2026-09-04

## 1. 目标

让 `.md` 文件里的标题 `#`–`######` 与嵌套无序列表**共同**构成导图层级，与 markmap 的层级语义对齐。

直接动机是一个真实痛点：典型的 markmap 风格笔记形如 `# 标题` / `## 章节` / 列表，而当前的 `parse` 从 H1 下一行开始找列表块，撞到 `## 章节` 就 `break`，`blockStart` 停在 -1，结果是一个没有子节点的空根、全文进 `tail`。数据不丢（`tail` 逐字保留，也不写回），但导图上什么都看不到。

## 2. 非目标

markmap 的默认选择器是 `h1,h2,h3,h4,h5,h6,ul,ol,li,table,pre,p>img:only-child`。本次**只采纳标题**，明确不做：

- 有序列表（`1.`）产生节点
- 表格、代码块、独立图片产生节点
- 「只读节点」这一新概念，以及多行块级内容的测量与布局
- markmap 的私有方言：`markmap:` frontmatter 选项、`<!-- markmap: fold -->` 魔法注释

后两项是刻意排除的。折叠状态若同时来自 frontmatter 的 `mindmap-collapsed` 和正文注释，写回时必须裁决谁赢，而这个插件的核心承诺是写回只有五条归一化——为了对齐一个没有兼容承诺的私有方言开这个口子，不划算。

三条形态决策（本次设计的前提，来自设计讨论）：

1. 只有标题参与层级，其他块级语法不产生节点
2. 解析双向（标题和列表项都读成节点），**写回单向**：图上新建的节点永远是列表项
3. 标题下的散文段落等块级内容不在图上显示，挂在前一个节点的 continuation 里原样重放

## 3. 数据模型

### 3.1 节点形态

形态由一个可选字段的存在与否判别，不设独立的 `kind` 字段——少一个可能与事实不一致的状态。

```ts
export interface HeadingForm {
  /** 1–6。仅用于解析期的层级归属计算，序列化不读它 */
  level: number;
  /** `#` 到文字之间的原始前缀，如 "## "、"###   " */
  prefix: string;
  /** 文字之后的原始尾随空白 */
  suffix: string;
  /** 该标题名下直接列表块的缩进单位；无可推断时为 null */
  indentUnit: string | null;
}

export interface MindNode {
  // ... 现有字段不变
  /** 存在即为标题节点；不存在即为列表项 */
  heading?: HeadingForm;
}
```

`isHeading(node): node is MindNode & { heading: HeadingForm }` 是唯一的判别入口，散落的 `node.heading !== undefined` 判断一律走它。

### 3.2 MindDoc 瘦身

三个字段被吸收进树：

| 删除 | 去处 |
|---|---|
| `headingPrefix` | `root.heading.prefix` |
| `headingSuffix` | `root.heading.suffix` |
| `headingGap` | `root.continuation` |

保留但语义变化：

- `indentUnit` —— 降级为兜底值，只在没有任何标题祖先能提供单位时使用
- `preamble` —— 从「H1 之前的内容」改为「**第一个节点行**（标题或列表项）之前的内容」
- `tail` —— 仅在文件里**零个节点行**时存放全文正文，否则恒为空串
- `hasHeading` —— 含义不变：根节点是否对应文件里一个真实的标题行

### 3.3 根节点恒为标题形态

**`root.heading` 永远存在**，包括文件里没有 H1、根节点文字取自文件名的情形（此时取 `level: 1`、`prefix: "# "`、`suffix: ""`，由 `hasHeading: false` 让序列化跳过标题行）。

理由：若虚拟根不带 `heading`，`isHeading(root)` 就是 false，而根既不是标题也不是列表项——第 6 节整套标题约束（不可删、不可拖、不带标记）会从根节点身上漏掉，退回成现有代码里那些散落的「id 是否等于根 id」判断。让 `isHeading` 一个谓词覆盖根节点，是这次能删掉那些特判的前提。

## 4. 解析

`parse` 从「定位单个列表块」改成对全文一次线性扫描。逐行分类为标题行、列表项行、其他三类。

### 4.1 围栏状态跟踪（新增的正确性要求）

当前 `FENCE_RE` 一命中就终止扫描，所以代码块里的 `## 假标题` 从来不构成威胁。改造后扫描不再终止，**围栏内的任何行都必须落入 continuation，绝不能产生节点**。

规则：记住开围栏的字符（`` ` `` 或 `~`）与长度，遇到同字符、长度 ≥ 它的行才算闭合。未闭合的围栏一直延续到文件末尾。

### 4.2 层级归属

维护一个标题栈。level 为 L 的标题挂到栈里最近的 level < L 的标题节点下；找不到就挂到根下。由此三种情形自然得到定义：

- `# T` 后直接跟 `### C`（跳级）—— C 挂在 T 下
- 文件里第二个 `# X` —— 挂在根下（画布需要单根，不引入虚拟根改变现有行为）
- 没有 H1、以 `## A` 开头的文件 —— 根是文件名的虚拟节点（`hasHeading: false`），A 是它的子节点

第三种情形正是第 1 节那个痛点的修复路径。

树深度与标题 level 因此不再严格对应。这不构成问题：序列化重放 `prefix`，不从 level 重算（见 5.1）。

### 4.3 列表项归属与缩进基准

列表项挂到最近的标题节点下。块内相对深度按**该块第一项的缩进为基准**逐块计算，不是全文一个基准——`## A` 下的列表和 `### B` 下的列表可能缩进不同。

每个列表块推断出的缩进单位存进它所属标题的 `heading.indentUnit`。推断算法沿用现有的 `detectIndentUnitString`（取第一个比基准更深的条目的缩进差作候选，再校验块内每个条目的缩进都恰好是 `候选.repeat(k)`），只是作用域从全文缩到单个块。

一个标题下可能有多个被散文隔开的列表块（列表、段落、列表）。`heading.indentUnit` 只有一个槽位，规则是**取第一个能推断出单位的块**；后续块若用了不同单位，会按该标题的单位重新缩进——这落在归一化第 4 条的「无法归纳出单一单位」情形里，属于已声明的行为，不是缺陷。这与「同一个标题下的列表在图上是同一片子树」的语义一致：它们本来就该用一致的缩进。

### 4.4 空行归属

沿用现有的一次前瞻，把归一化第 2 条原样搬过来：

1. 收集连续空行
2. 前瞻下一个非空行
3. 是列表项 → 丢弃这些空行（松散列表压缩成紧凑列表，即归一化第 2 条）
4. 否则 → 追加进**当前节点**的 continuation
5. 当前还没有任何节点 → 进 `preamble`

所以 `- a\n\n## A` 里那个空行进 `a.continuation`，`# T\n\n- a` 里那个空行进 `root.continuation`（替代原来的 `headingGap`），两者都逐字节还原。

## 5. 序列化

一次前序遍历。标题节点写 `prefix + text + suffix`，列表项写 `unit.repeat(listDepth) + bullet + " " + composeLine(node)`。两者后面都紧跟自己的 continuation 各行。

### 5.1 永不重算 `#`

**序列化永远重放 `heading.prefix`，绝不从 `level` 重算 `#` 的个数。**

这是整个方案的解耦点：层级归属规则（4.2）怎么调整都不会改写一个字节，「图上显示的层级」与「文件的字节」彻底分离。改 `serializer.ts` 时不得引入任何形如 `"#".repeat(level)` 的代码。

### 5.2 listDepth 与缩进单位继承

`listDepth` 是**从最近的标题祖先算起**的深度，不是树深度。一个 H3 下的一级列表项，树深度是 3，文件里的缩进是 0。

缩进单位取最近标题祖先的 `heading.indentUnit`；为 null 时继续向上找祖先标题；全都没有则用 `doc.indentUnit`，最终兜底 `"  "`。

拖拽跨块移动时行为因此自动是对的：节点落到哪个标题下，就用那个标题的单位重新缩进。

### 5.3 写回归一化仍是五条，第 4 条变强

第 4 条从

> 缩进单位混用、无法归纳出单一一致单位时，统一改写为每层 2 空格

改为

> 缩进单位按标题各自推断、各自保真。两种情形下会被改写为每层 2 空格：某个列表块**内部**混用、无法归纳出单一单位；或**同一个标题名下**的多个列表块彼此单位不一致（此时统一到第一个能推断出的单位，见 4.3）。

不同标题名下的列表块使用不同单位是**保真**的，不触发改写。

这是严格的增强。若不做 4.3 的分块存储而沿用全文一个 `indentUnit`，一份 `## A` 下用 2 空格、`## B` 下用 4 空格的文件会被全文改写——而改造前它不会，因为第二个块根本不解析、原样待在 `tail` 里。那是本次改造引入的真实倒退，靠分块存储消掉。

其余四条不变。

## 6. 编辑约束与不变量

### 6.1 list-before-heading 不变量

**一个标题节点的 `children` 里，列表项形态的子节点必须全部排在标题形态的子节点之前。**

这不是风格问题。`# T` 的子节点若排成 `[- a, ## A, - new]`，序列化出来 `- new` 落在 `## A` 之后，重新解析时它就跑进 A 名下了——一次「加子节点」静默改变了树的形状。

`addChild`、`addSibling`、`moveNode` 的落点计算都必须维护它。`tree-ops.ts` 里加一个 `firstHeadingIndex(children)` 辅助函数，所有插入位置对它做 clamp。

### 6.2 标题节点的操作矩阵

| 操作 | 标题节点 | 理由 |
|---|---|---|
| 加子节点（Tab） | 允许，产出列表项，插在第一个标题子节点之前 | 决策 2 + 6.1 |
| 加兄弟（Enter） | no-op | 列表项不能作标题的兄弟 |
| 删除 | 拒绝 | 会连带删掉图上不可见的 continuation |
| 拖拽（作为源） | 拒绝 | 同上 |
| 拖拽（作为落点） | 允许，受 6.1 约束 | |
| 折叠 | 允许 | 纯视图状态，不改文件正文 |
| 标记 | no-op | 见 6.3 |
| 编辑文字 | 允许，跳过 `parseMarks` | 见 6.3 |
| 加粗 / 斜体 / 链接 | 允许 | 标题行可以含行内 Markdown |

### 6.3 约束 #8 从根节点推广到所有标题节点

AGENTS.md 第 8 条「根节点永不携带标记」推广为「**标题节点**永不携带标记」。理由不变，且更强：标题行没有承载行内标记的位置，真写进去 `(p1)` 会出现在 Obsidian 的大纲面板和链接文本里。

落地三处：

- 解析标题行时不调 `parseMarks`（`## (p1) A` 的 `(p1)` 就是标题文字的一部分）
- `setMarks` / `toggleMark` 对标题节点 id 是 no-op
- `commitText` 对标题节点直接存原文，不走 `parseMarks`

### 6.4 折叠状态

`collapse-state.ts` 不改。路径仍按节点 text 拼接，标题节点同样有 text。标题引入后路径变长、重名概率上升，沿用现有的「首个命中、失配静默忽略」语义。

## 7. 视图层

标题节点必须有视觉区分，否则用户不理解为什么删不掉、按 Enter 没反应。复用现有 `.mm-root` 的模式，加一个 `.mm-heading` 类。

`toolbar.ts` 按 6.2 的矩阵置灰按钮（现在只对根节点禁用「标记」，改为对所有标题节点禁用「标记」「删除」「加兄弟」）。`drag.ts` 拒绝标题节点作为拖拽源，落点索引按 6.1 clamp。

按 AGENTS.md「自动化测不到什么」一节：本节全部改动需要在真实 Obsidian 里人工确认，`docs/MANUAL-VERIFICATION.md` 要加项。实现报告里不得声称视觉或交互行为正确。

## 8. 已知局限（写入 README）

- 不带空格的 `##` 是合法的 CommonMark 空标题，本插件不认。这条空格要求正是 `#tag` 不被误判成标题的原因。不认的标题进 continuation 原样保留，不显示。
- Setext 标题（`A` 后跟 `===`）不认，同样保留但不显示。
- 带前导空格的标题（CommonMark 允许最多 3 个）不认，必须顶格。这与现有 `ANY_HEADING_RE` 的行为一致，且是「列表项续行里的 `  ## x` 不被误判成标题」所依赖的性质。
- 列表块的边界定义为「连续的列表项条目」，条目之间的散文进前一条目的 continuation 且不切断块。因此 `- a` / 空行 / 散文 / `    - b` 这种形态里的 `- b` 会被当成 `a` 的子节点，而 CommonMark 认为散文已经结束了列表、`    - b` 是代码块。与下面那条 4 空格的局限同源，同样不在本次范围内修。
- ATX 闭合序列 `## A ##` 会把 `A ##` 整个当作节点文字。字节能还原，但图上文字带尾巴。
- 有序列表、表格、代码块、图片不产生节点（第 2 节非目标）。
- 空行后 4 空格缩进的 `- a` 在 CommonMark 里是代码块，本插件仍当列表项。**这是改造前就存在的行为，不在本次范围内修。**

## 9. 测试

### 9.1 round-trip 语料

`tests/roundtrip.test.ts` 的 `CORPUS` 按 AGENTS.md 第 2 条只能加不能放宽。新增语料：

- 多标题多列表块
- 标题后紧跟散文段落
- 标题跳级（H1 → H3）
- 文件里第二个 H1
- 无 H1、以 H2 开头
- 标题文字含 `(p1)`
- 围栏内含假标题与假列表项（含未闭合围栏）
- **不同标题**名下分别用 2 空格 / 4 空格 / tab 的三个列表块 —— 进 `CORPUS`，断言逐字节相等
- **同一标题**名下用不同单位的两个列表块 —— **不进 `CORPUS`**，单独断言它按 5.3 统一到第一个单位（这条不是 round-trip 恒等的，混进 `CORPUS` 会逼实现者去放宽语料，正是 AGENTS.md 第 2 条禁止的动作）
- H6 之下的深层列表
- 松散列表与标题混排（验证 4.4 的空行归属）

fast-check 生成器扩展成能生成含标题的文档树。

### 9.2 单元测试

- 标题栈的归属规则（跳级、第二个 H1、无 H1）
- `listDepth` 与缩进单位的继承链
- 6.1 不变量在 `addChild` / `addSibling` / `moveNode` 三个入口上的维持
- 6.2 矩阵里每条拒绝路径
- 6.3 的三处 no-op

### 9.3 对抗性输入

按 AGENTS.md 门禁一节：`parser.ts` 是手写扫描器，只交正确性测试不够，必须同时带

- 时间上限断言（防病态输入卡死主线程）
- 结构化输出断言（防退化成「整段都当 continuation」却因 round-trip 恒等而蒙混过关）

重点构造：几千行的标题/列表交替、大量未闭合围栏、每行都是标题的文件。
