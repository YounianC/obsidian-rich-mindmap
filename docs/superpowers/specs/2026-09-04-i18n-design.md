# 界面文字 i18n（中文 / English，设置页可切换）— 设计文档

日期：2026-09-04

## 1. 目标

插件的全部面向用户字符串支持中文与英文，语言在设置页切换。

现状是 48 处中文字符串硬编码在 7 个文件里，`README` 两份都写着「界面文字目前只有中文，尚未做 i18n」，`AGENTS.md` 第 10 条更把「面向用户的字符串一律中文」定为硬约束。本设计**推翻那条约束**，改为「一律走 `t()`」。

## 2. 非目标

- 不做繁体中文。`zh-TW` / `zh-HK` 归到简体。
- 不做第三种语言，也不做外部 JSON 加载。加语言就是往 `src/i18n.ts` 的表里加一列。
- 不本地化 `manifest.json` 的 `description`：Obsidian 不支持本地化 manifest。
- 不本地化用户笔记内容。唯一例外是新建文件的默认名（见第 6 节），那是插件生成的新文件，不是改写已有内容。

## 3. 四条形态决策（来自设计讨论）

1. **语言选择**：「跟随 Obsidian / 中文 / English」三选，默认跟随。
2. **新建文件的默认名跟随语言**：中文 `未命名思维导图.md`、英文 `Untitled Mindmap.md`，文件里的 H1 同步。只影响新建，已有文件不改名不重写。
3. **`minAppVersion` 抬到 1.8.7**，直接用 `getLanguage()`（`@since 1.8.7`）与 `removeCommand()`（`@since 1.7.2`），不写降级分支。
4. **命令名立即生效**：切换语言时 `removeCommand()` 后用新文案重新 `addCommand()`。

## 4. 语言解析与模块边界

```ts
export type Locale = "zh" | "en";
export type LanguageSetting = "auto" | "zh" | "en";

/** 纯函数：设置值 + Obsidian 的语言码 → 实际语言 */
export function resolveLocale(setting: LanguageSetting, appLanguage: string): Locale {
  if (setting !== "auto") return setting;
  return appLanguage.startsWith("zh") ? "zh" : "en";
}
```

`MindmapSettings` 新增 `language: LanguageSetting`，`DEFAULT_SETTINGS.language = "auto"`。

### 4.1 `src/i18n.ts` 刻意不 import obsidian

`getLanguage()` 只在 `main.ts` 一处调用，结果作为参数传进 `resolveLocale`。这样字典与解析逻辑可以直接单测，不需要 mock Obsidian。

### 4.2 但它不放进 `src/model/`

`t()` 读模块级的当前语言，同样的入参在 `setLocale()` 前后返回不同结果——**它不是纯函数**。`scripts/check-purity.mjs` 只校验四条禁令（`import obsidian`、`document`、`window`、`HTMLElement`），一个字典加一个可变变量能通过校验，但放进纯函数层是在骗人：那一层的契约是纯粹性，不是「碰巧没碰 DOM」。

### 4.3 模块级可变状态是这个仓库的异类，代价要写明

替代方案是把 `t` 当依赖注入逐层传下去（`createToolbar(host, handlers, t)` 等），更符合本仓库「显式注入回调」的风格。否决理由：要改 6 个文件的构造函数签名（`toolbar` / `controls` / `marks-panel` / `node-el` / `interaction` / `view`），而翻译表不是逻辑、注入换不来可测性收益——48 个字符串换 6 处签名污染，不值。

代价是 `t()` 自己不通知任何人。**语言变更后必须由 `main.ts` 显式触发重渲染**，这条要写进 `t()` 的 doc 注释里，它是本方案唯一的真实陷阱。

## 5. 字符串表

```ts
const zh = {
  "command.toggleView": "切换思维导图 / 源码视图",
  // …
} as const;

export type MessageKey = keyof typeof zh;

const en: Record<MessageKey, string> = {
  // …
};
```

由 `zh` 推导出 key 联合类型，英文表声明为 `Record<MessageKey, string>`。于是**漏一条英文翻译是编译错误**，调用处拼错 key 也是编译错误。

### 5.1 插值

8 条需要插值：`main.ts` 的两条失败通知（`{error}`）、`marks-panel.ts` 与 `node-el.ts` 各自的三条角标无障碍标签（`优先级 {n}` / `进度 {n}%` / `旗帜 {color}`）、以及折叠角标的提示（`已折叠 {count} 个子节点，点击展开`）。

`t(key, params?)` 对 `{name}` 做一次替换，不引入模板引擎。参数缺失时保留 `{name}` 字面量、不抛异常——面向用户的文案出问题不该让渲染管线崩掉。

折叠角标显示的 `▸ N` 本身**不进字典**：三角符号加数字不含语言，翻译它没有意义。要翻译的是它的 `title`。

### 5.2 待翻译的 48 处按文件

由 `git ls-files` 扫全部 `src/**/*.ts`（剥离注释后匹配双引号与反引号里的中文）得到。视图与主层 47 处，`src/model/` 里 1 处：

| 文件 | 处数 | 内容 |
|---|---|---|
| `view/toolbar.ts` | 15 | 3 个样式项、7 个按钮标签、4 条禁用原因 |
| `view.ts` | 8 | `addAction` 提示、标签页标题兜底、外部修改通知、无文件时的文件名兜底、错误卡片 3 条、链接输入占位符 |
| `main.ts` | 7 | 2 个命令名、2 个菜单项、3 条通知 |
| `view/marks-panel.ts` | 6 | 3 个分区标题 + 3 条角标无障碍标签 |
| `settings.ts` | 4 | 现有设置项的 name/desc，声明式与 `display()` 兜底各一份 |
| `view/node-el.ts` | 4 | 3 条角标无障碍标签 + 折叠角标提示 |
| `view/controls.ts` | 3 | 3 个缩放按钮提示 |
| `model/new-file.ts` | 1 | `DEFAULT_MINDMAP_BASENAME`（见第 6 节） |

去重之后是 **47 个 key**：`view/node-el.ts` 与 `marks-panel.ts` 的三条角标标签文案完全重复（两处都写 `优先级 {n}` / `进度 {n}%` / `旗帜 {color}`），`切换到源码模式` 在 `view.ts` 里出现两次，`settings.ts` 的 name/desc 在声明式与兜底两条路径里各写一遍。i18n 顺带消掉这些重复。

`view.ts` 里那条 `"未命名.md"` 是「没有打开任何文件」时喂给 `parse()` 的文件名兜底，会成为根节点文字。它只在退化状态下可见，但仍然给一个 key（英文 `Untitled.md`）——否则第 9 节的门禁会命中它，而为它单开一条豁免名单不值得。

## 6. 新建文件名与纯函数层

`uniqueMindmapPath(folderPath, basename, exists)` —— `basename` 是**必需参数，不给中文默认值**，否则默认值会静默留存、i18n 形同虚设。

`DEFAULT_MINDMAP_BASENAME` 从 `new-file.ts` 删除；`main.ts` 传 `t("newFile.basename")`。`newMindmapContent(title)` 已经接收 title，不用改。

纯函数层的边界因此**不需要变动**：`src/model/**` 在这次改动后不含任何面向用户的字符串。

## 7. 生效范围

`main.ts` 新增 `applyLanguage()`，做三件事：

1. `setLocale(resolveLocale(this.settings.language, getLanguage()))`
2. `removeCommand()` 两个命令 id，再用新文案 `addCommand()`
3. 遍历 `app.workspace.getLeavesOfType(MINDMAP_VIEW_TYPE)`，让每个导图视图重建图层

`onload()` 与设置变更时各调一次。

### 7.1 设置变更的钩子

`SettingControlBase` 没有 `onChange`。真正的钩子是 `PluginSettingTab.setControlValue(key, value)`（`@since 1.13.0`，注释写明「Mutates and persists `this.plugin.settings`」）。覆写它：先落盘（`await super.setControlValue(key, value)`），再在 `key === "language"` 时调 `plugin.applyLanguage()` 与 `this.update()`（`update()` 在基类 `SettingTab` 上，`@since 1.13.0`）刷新设置页自身的文案。

### 7.2 视图重建必须复用既有机制

置 `this.layers = null` 再 `render()`，与 `setViewData` 完全同一条路径。**不得另写一套重建逻辑**：`render()` 的重建分支靠 `eventsAttached` 守卫防止监听器堆叠（AGENTS.md 第 6 条，「一个滚轮档位变成 `factor^N` 倍缩放」就是这么来的）。视口与选中会保留。

`MindmapView` 因此新增一个公开方法（`refreshLocale()`），只做这两行。

### 7.3 各处的生效时机

| 位置 | 何时变 |
|---|---|
| 设置页自身 | 立即（`update()`） |
| 文件右键菜单 | 立即（每次打开菜单时构建） |
| 之后弹出的通知 | 立即 |
| 工具栏、缩放控件、标记面板、错误卡片 | 立即（图层重建） |
| 命令面板里的命令名 | 立即（重注册） |
| 无文件时的标签页标题兜底 | 由 Obsidian 决定何时重新调用 `getDisplayText()`，插件控制不了 |

## 8. `minAppVersion`

`manifest.json` 抬到 `1.8.7`。

`versions.json` 是**按版本记最低要求**的映射：`0.1.1` 那条仍为 `1.5.0`，新版本另加一条指向 `1.8.7`。

**设置页的 `display()` 兜底路径要保留，并同步加语言下拉**：声明式 `getSettingDefinitions()` 是 `@since 1.13.0`，而 1.8.7–1.12.x 仍在支持区间内，那些版本走 `display()`。两条路径的文案必须一致。

## 9. 第五条门禁：`scripts/check-i18n.mjs`

扫描 `src/main.ts`、`src/settings.ts`、`src/view.ts`、`src/view/**`，在字符串字面量里发现中文即失败。

这是防止以后新增字符串忘记走 `t()` 的**唯一机械手段**——四条现有门禁看不到这件事，i18n 会缓慢腐烂：某天有人加一条中文通知，测试全绿，英文用户看到一句中文。

实现要点与代价：这个仓库的注释全是中文，所以必须先剥离注释（`//` 行注释与 `/* */` 块注释）再匹配**双引号与反引号**里的中文。

反引号不能漏——这次设计过程中第一版调研只匹配双引号，结果整个漏掉了 `view/node-el.ts`（4 处模板字符串），差点让 spec 的文件清单少一个文件。

剥离逻辑本身要有单测，至少覆盖两种会让朴素实现出错的形态：注释里出现引号、字符串里出现 `//`（例如 URL）。朴素的正则先删 `//` 到行尾会把 `"http://x"` 截断。

`src/model/**` 不在扫描范围内：那一层改动后不含面向用户字符串，而它的中文注释密度最高，扫它只会制造噪音。`src/i18n.ts` 也排除——它就是中文表所在。

## 10. 测试

- `resolveLocale`：`auto`+`zh` / `auto`+`zh-TW` / `auto`+`en` / `auto`+`ja` / 三种显式取值
- 字典完整性：编译期已由类型保障，另加运行时断言两表 key 集合相等、且无空串值（类型系统挡不住 `""`）
- `t()` 插值：单参数、多参数、参数缺失时保留 `{name}` 原样而不是抛异常
- `t()` 在 `setLocale` 前后返回不同结果（把模块级状态的行为钉住）
- `uniqueMindmapPath` 传英文基名时的去重编号
- `scripts/check-i18n.mjs` 的注释剥离逻辑单测

## 12. 已知局限

- `zh-TW` / `zh-HK` 显示简体中文
- `manifest.json` 的 `description` 只有英文，Obsidian 不支持本地化 manifest
- 无文件时的标签页标题兜底文案，切换语言后何时刷新由 Obsidian 决定
- 只支持两种语言；加语言要改 `src/i18n.ts` 的表并重新构建，不支持用户自备语言包
- 已创建文件的名字不会因为切换语言而改变（这是刻意的：改名会动用户的数据）
