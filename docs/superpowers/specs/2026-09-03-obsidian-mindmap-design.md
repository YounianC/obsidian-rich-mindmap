# Obsidian 本地思维导图插件 — 设计文档

日期：2026-09-03
状态：已确认

## 1. 目标

在 Obsidian 中提供一个本地思维导图视图，支持完整的读写编辑闭环、截图参考的标记系统（优先级/进度/旗帜）与悬浮工具栏，外观精致且跟随 Obsidian 主题。

两条硬性要求：

1. **美观** — 贝塞尔曲线连线、分支自动配色、层级字号、亮/暗主题自适应。
2. **原始数据对 AI 友好** — AI 能直接读出清晰结构，也能自己写文件。

## 2. 非目标

- 不内置 AI 调用（无 API Key、无网络请求）。AI 协同方式是：外部 AI 直接编辑 `.md` 文件，插件监听文件变化刷新画布。
- 不做自由坐标布局（思维导图本质是树，坐标是冗余信息）。
- 不做多人协作、不做版本历史（交给 Obsidian 与 git）。
- 第一版不做左右双向平衡布局，只做根节点在左、整树向右展开。

## 3. 数据格式

### 3.1 文件形态

存储就是**普通 Markdown 文件**。结构：

```markdown
---
mindmap: true
mindmap-collapsed:
  - 呼叫中心/业务向
---

# 工作内容

- 呼叫中心
  - (p1) 管理向
    - 任务安排
    - OKR等问题思考
  - 业务向
    - (p1) 看系统的数据：报错，报警，监控
      - 适当减少精力，培养组员
    - (p3 30%) 部分开发自测
    - (p2) 回答各类业务问题 [[业务手册]]
- WP
  - (flag:red) 理解业务流程
```

- **根节点** = 文件中第一个一级标题（`# `）的文本。若文件没有一级标题，则使用文件名作为根节点，且序列化时不写入标题行。
- **树** = 该标题之后**第一段连续的无序列表块**。列表项 `- ` 的缩进深度决定层级。
- 列表块在遇到以下任一情况时终止，其后所有内容作为不透明尾块原样保留：空行后跟非列表行、任意标题行、有序列表项（`1. `）、代码块围栏（```` ``` ````）。列表项内部的续行（缩进的非 `- ` 开头行）作为该节点文本的一部分，写回时保持原缩进。
- 一个列表项对应一个节点，节点文本 = 列表项内容（去掉行内标记后剩余部分），保留其中所有 Markdown 行内语法（`[[链接]]`、`#标签`、`**加粗**`、`` `代码` ``）。

### 3.2 行内标记语法

节点文本**最前面**的一个括号组，当且仅当组内**每一个**空格分隔的 token 都匹配已知标记模式时，才被解析为标记；否则整个括号组按普通文字处理。

| Token 模式 | 含义 | 取值 | 渲染 |
|---|---|---|---|
| `p<n>` | 优先级 | `p1`–`p7` | 彩色数字圆标，p1 红 / p2 橙 / p3 黄 / p4–p7 灰 |
| `<n>%` | 进度 | `0`–`100` 整数 | 映射到 7 档饼图图标，见下表 |
| `flag:<color>` | 旗帜 | `red` `orange` `yellow` `green` `blue` `purple` `gray` | 对应色旗标 |

**进度档位映射**（按区间取档，边界含左不含右）：

| 输入 | 档位 | 图标 |
|---|---|---|
| `0%` | 0 | 时钟 |
| `1%`–`24%` | 1 | 1/6 饼 |
| `25%`–`41%` | 2 | 2/6 饼 |
| `42%`–`58%` | 3 | 半饼 |
| `59%`–`75%` | 4 | 4/6 饼 |
| `76%`–`99%` | 5 | 5/6 饼 |
| `100%` | 6 | 对勾 |

面板点选时写入该档的代表值：`0%` `17%` `33%` `50%` `67%` `83%` `100%`。AI 手写的任意整数百分比按上表落档，且**原值保留不被改写**（例如 `60%` 渲染为 4 档，写回仍是 `60%`）。

规则：

- 三类标记各自最多出现一次；重复出现时以最后一次为准。
- 顺序不敏感：`(p1 60% flag:blue)` 与 `(flag:blue p1 60%)` 等价。
- 序列化时统一按 `优先级 → 进度 → 旗帜` 顺序输出，token 间单空格，括号组后紧跟一个空格再接节点文本。
- 空标记集不输出括号组。

**歧义处理示例**：

- `- (备注) 这是什么` → `备注` 不匹配任何模式 → 节点文本为 `(备注) 这是什么`，无标记。
- `- (p1 备注) 任务` → 组内存在不匹配 token → 整组按文字处理 → 节点文本为 `(p1 备注) 任务`。
- `- (p1) (备注) 任务` → 首组全部匹配 → 标记 `p1`，节点文本为 `(备注) 任务`。

**为什么选这套语法**：AI 只需写一行普通 Markdown 列表项即可新增带标记的节点，无需处理 id、坐标或 JSON 转义；人读也无障碍。相比 `#p1` 标签方案，它不会污染 Obsidian 的标签面板。

### 3.3 折叠状态

折叠是视图状态而非内容，因此存在 frontmatter 的 `mindmap-collapsed` 中，值为折叠节点的**路径数组**（从根到该节点的文本以 `/` 连接）。

节点文本中的 `/` 转义为 `\/`，反斜杠转义为 `\\`。

路径不唯一时（同层同名兄弟节点）以第一个匹配为准；路径匹配失败时忽略该条目。这些都是已知的可接受降级，代价仅为折叠状态偶发错位，不影响内容。

## 4. 文件安全

插件会重写用户文件，因此以下约束是硬性的：

1. frontmatter 中除 `mindmap`、`mindmap-collapsed` 两个键外，其余键与顺序**原样保留**。
2. 导图列表块**之外**的所有内容（标题前的前言、列表块之后的段落/代码块/其他列表）在读取时作为不透明文本块保存，写回时原样附加，不参与渲染也不被修改。
3. 缩进读取时兼容 2 空格 / 4 空格 / Tab（按文件中首次出现的缩进单位推断）；写入时统一为 2 空格。
4. 保存走 Obsidian `TextFileView` 的 `getViewData`/`setViewData` 机制配合 400ms 防抖，**不直接调用 `vault.modify`**，避免与编辑器争抢写入。
5. 往返稳定性由属性测试保证：对任意合法 `MindDoc`，`parse(serialize(doc))` 深度等于 `doc`；对任意规范化 Markdown，`serialize(parse(md)) === md`。
6. 允许且仅允许三条写回归一化，其余任何内容变化都是缺陷：
   - 不以换行结尾的文件被补上尾换行；
   - 松散列表（列表项之间存在空行）被写成紧凑列表；
   - CRLF（`\r\n`）换行在读取时归一化为 LF（`\n`），因此 CRLF 文件保存后换行符统一为 LF。

   第三条是 2026-09-03 的决定：CRLF 文件此前会被解析为空导图（正则以 `(.*)$` 锚定，而 `.` 不匹配 `\r`），数据不丢但视图不可用。读取时归一化是改动最小的修法；代价是 CRLF 文件首次保存会被 git 显示为全量改动。

## 5. 架构

技术栈：TypeScript + esbuild + Obsidian API + vitest。渲染使用原生 DOM，不引入 React（包体更小、启动更快，符合 Obsidian 插件惯例）。

渲染采用**混合方案**：连线用 SVG（贝塞尔曲线质量高），节点用绝对定位的 HTML `div`（可用真实字体、自动换行、承载 Markdown 行内元素）。纯 SVG 文本在测量与换行上代价过高，纯 DOM 无法绘制优质曲线。

### 5.1 模块划分

纯函数层（`model/`、`view/layout.ts`）与 DOM 层严格分离，前者全部可单测。

```
manifest.json
package.json
tsconfig.json
esbuild.config.mjs
styles.css
src/
  main.ts              插件入口：注册视图 / 命令 / 设置 / 文件菜单
  settings.ts          设置项定义与设置面板
  view.ts              MindmapView extends TextFileView，编排下列模块
  model/               ← 纯函数，无 DOM 依赖
    types.ts           MindNode / Marks / MindDoc 类型定义
    marks.ts           行内标记 解析 ↔ 格式化
    parser.ts          Markdown → MindDoc
    serializer.ts      MindDoc → Markdown
    tree-ops.ts        增 / 删 / 改文字 / 移动 / 折叠（不可变操作）
  view/
    layout.ts          纯布局算法：树 + 节点尺寸 → 坐标
    measure.ts         离屏测量节点尺寸
    renderer.ts        SVG 连线 + DOM 节点渲染与差量更新
    camera.ts          缩放 / 平移状态与变换
    interaction.ts     选择 / 键盘 / 拖拽
    toolbar.ts         悬浮工具栏
    marks-panel.ts     标记面板（优先级 / 进度 / 旗帜）
tests/
  marks.test.ts
  parser.test.ts
  roundtrip.test.ts
  layout.test.ts
```

### 5.2 模块契约

| 模块 | 职责 | 接口 | 依赖 |
|---|---|---|---|
| `marks.ts` | 行内标记双向转换 | `parseMarks(text) → {marks, rest}`；`formatMarks(marks) → string` | 无 |
| `parser.ts` | Markdown 解析 | `parse(md, fileName) → MindDoc` | `marks`, `types` |
| `serializer.ts` | Markdown 生成 | `serialize(doc) → string` | `marks`, `types` |
| `tree-ops.ts` | 树结构变更 | `addChild` / `addSibling` / `remove` / `setText` / `setMarks` / `move` / `toggleCollapse`，均返回新树 | `types` |
| `layout.ts` | 坐标计算 | `layout(root, sizes, opts) → Map<id, Rect>` + 连线控制点 | `types` |
| `measure.ts` | 尺寸测量 | `measure(nodes, container) → Map<id, Size>` | DOM |
| `renderer.ts` | 绘制 | `render(doc, layoutResult, camera)` | DOM |
| `camera.ts` | 视口 | `zoom` / `pan` / `fit` / `toScreen` / `toWorld` | 无 |
| `interaction.ts` | 输入事件 → 意图 | 发出 `intent` 事件，由 `view.ts` 转成 `tree-ops` 调用 | DOM |

### 5.3 数据流

```
.md 文件
  │ parse
  ▼
MindDoc ──────────────────► measure ──► layout ──► renderer ──► 画布
  ▲                                                                │
  │ tree-ops (不可变)                                              │ 用户输入
  └──────────────── view.ts ◄──── interaction / toolbar / panel ◄──┘
  │ serialize + 400ms 防抖
  ▼
.md 文件
```

外部 AI 修改文件时：`vault.on('modify')` → 若非本插件自身写入 → 重新 `parse` 并保留当前选中与视口。

### 5.4 布局算法

自底向上两趟：

1. 后序遍历计算每棵子树的垂直跨度（叶子跨度 = 自身高度 + 间距）。
2. 前序遍历分配坐标：节点 x = 父节点 x + 父节点宽度 + 水平间距；节点 y = 其子节点跨度的中心；叶子节点按顺序占据槽位。

该算法保证任意两节点包围盒不重叠。折叠节点的子树跨度按 0 计算。

连线为三次贝塞尔曲线，控制点取父子 x 中点，形成截图中的横向 S 形；线宽随层级递减。

### 5.5 打开方式

- 注册视图类型 `mindmap`（`MindmapView extends TextFileView`）。
- 命令面板「以思维导图打开 / 切回源码」与文件右键菜单项，在当前标签页切换 `markdown` ↔ `mindmap` 视图状态。
- 设置项「带 `mindmap: true` 的文件自动用导图打开」，默认开启；实现方式为监听 `file-open` 后切换视图状态。
- 任何时候都能切回源码模式查看原始 Markdown。

## 6. 交互

### 6.1 键盘

| 按键 | 行为 |
|---|---|
| `Tab` | 为选中节点添加子节点并进入编辑 |
| `Enter` | 添加兄弟节点并进入编辑 |
| `F2` / 双击 | 编辑选中节点文字 |
| `Esc` | 退出编辑（保留输入）/ 取消选中 |
| `Delete` / `Backspace` | 删除选中节点及其子树 |
| 方向键 | 在树中移动选中（上下同层、左到父、右到首个子节点） |
| `Space` | 折叠 / 展开选中节点 |
| `Cmd/Ctrl + 滚轮` | 缩放 |
| 空白处拖拽 | 平移 |

节点拖拽可改变父节点与同层顺序，拖拽时显示插入位置指示线。

### 6.2 悬浮工具栏

选中节点时贴近节点出现，按钮均带 tooltip：

添加子节点 · 添加兄弟节点 · 删除节点 · 文字样式（加粗/斜体/删除线）· 标记面板 · 插入链接 · 折叠子树 · 节点样式

### 6.3 标记面板

三段式弹层，与截图一致：

- **优先级**：1–7 彩色数字圆标
- **进度**：7 档饼图（0% 时钟图标 → 100% 对勾）
- **旗帜**：7 色旗标

点选即写入行内标记；再次点击同一项取消该标记。

## 7. 外观

- 连线：三次贝塞尔曲线，线宽随层级从 3px 递减至 1.5px。
- 配色：一级分支按固定色相序列分配（紫、蓝、青、绿、橙、红、粉），子树继承父分支色相。
- 节点样式：根节点为填充圆角矩形；一二级节点为无边框文字 + 底部横线；叶子节点为纯文字 + 细底线（对应截图）。
- 字号：根 18px，一级 16px，二级 15px，三级及以下 14px。
- 主题：所有颜色取自 Obsidian CSS 变量（`--text-normal`、`--background-primary`、`--interactive-accent` 等），亮/暗主题自动跟随。
- 画布右上角控件：适应窗口、缩放百分比、放大/缩小。

## 8. 错误处理

| 情况 | 处理 |
|---|---|
| 文件无一级标题 | 用文件名作根节点，序列化时不写标题行 |
| 文件无列表块 | 显示仅含根节点的画布，编辑后正常写入列表块 |
| 缩进层级跳跃（如从 1 级直接到 3 级） | 按最近合法父节点挂载，并在写回时规范化缩进 |
| 解析失败（异常） | 画布显示错误提示与「切换到源码模式」按钮，**不写入文件** |
| 外部修改与本地未保存编辑冲突 | 以文件为准重新解析，通过 Notice 告知用户 |
| 标记值越界（如 `p9`、`150%`） | 不匹配已知模式，按普通文字处理 |

## 9. 测试策略

**纯函数层（vitest，自动化）**

- `marks.test.ts`：各类标记解析、组合、顺序无关、歧义降级、格式化输出规范。
- `parser.test.ts`：层级推断、多种缩进、无标题、无列表、缩进跳跃、非列表内容保留。
- `roundtrip.test.ts`：属性测试 —— 随机生成 `MindDoc` 验证 `parse(serialize(doc))` 等于原值；语料库 Markdown 验证 `serialize(parse(md)) === md`；frontmatter 未知键保留。
- `layout.test.ts`：包围盒不重叠、父节点居中于子节点跨度、折叠子树不占空间。

**视图层（人工验证，由实现者完成）**

建立测试 vault 与热重载流程，逐项截图验证渲染与交互，包含亮/暗主题各一遍。不要求用户代为确认。

## 10. 已确认的决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 存储格式 | 纯 Markdown 缩进列表 + 行内标记 | AI 读写成本最低；Obsidian 原生功能全部可用 |
| AI 集成 | 不内置 | 零配置零密钥；外部 AI 直接改文件，插件监听刷新 |
| 渲染方式 | SVG 连线 + DOM 节点 | 兼得曲线质量与文本排版能力 |
| UI 框架 | 无（原生 DOM） | 包体小、启动快、契合 Obsidian 惯例 |
| 布局方向 | 根在左，向右展开 | 与参考截图一致，实现简单 |
| 折叠状态存储 | frontmatter | 视图状态不应污染正文 |
